## 总结论

PitLore 的完整闭环今天不存在任何等价物——这是经六路调研+对抗核查后的可靠结论——但它的每个单项都已有强先例，且窗口正从两侧收窄：检索/记忆半场已被 Byterover、Memorix、mem0 和各家默认开启的内置记忆商品化，门禁半场是 Semgrep/Codacy/CodeRabbit 的红海，可移植性叙事被 AGENTS.md 稀释。真正无人占据的车道是那个"组合"：从真实 bug-fix 蒸馏出带可执行检测器的结构化、消毒、版本化教训，经 MCP 跨 agent 编码前注入 + 编码后硬拦截，并以 npm/GitHub 式 packs 流通——学术界（SWE-Exp、ReasoningBank）已证明机制有效，工业界无人产品化。四个问题的答案依次是：不存在（Q1）、可行但投毒防护必须是第一天的设计而非事后补丁（Q2，ClawHavoc 是前车之鉴）、完全可行且是最强的一环（Q3）、可行但属 roadmap 长跑而非 hackathon 交付物（Q4）。成败不取决于点子（点子已被充分验证），而取决于两个执行硬骨头：蒸馏出的教训是否真的通用而不过泛化，以及自动生成的检测器误报率是否低到团队不会关掉 gate。对 Build Week：演示完整闭环 + Codex 优先叙事 + 硬门禁做高潮 + 主动回应记忆退化论文与投毒风险，这套组合在当前赛道上没有第二个团队能讲。

### 已采纳的交付路线（2026-07-15）

1. **Phase 1：本地个人 / 团队可用**——只交付 local-first 的 fix → Lesson → retrieve → check 闭环；团队通过私有 Git 共享，不建设服务端。
2. **Phase 2：开源共享**——公开 Pack、Git URL 安装、sanitize、版本与供应链治理；先复用 GitHub，不建设网站。
3. **Phase 3：网站进化**——只有开源 Pack 出现持续安装/贡献，并产生组织权限、审计或托管需求后，才建设 Registry 网站与商业化能力。

这一路线把最难的公共投毒和双边市场问题后置，先验证 PitLore 唯一可守的差异：同一条真实修复经验能否同时改善 agent 编码并形成低误报的确定性门禁。

## 四个核心问题

### Q1 市面上是否已存在同类机制？

不存在完整闭环等价物。PitLore 的五步闭环（捕获真实 bug-fix → 蒸馏为抽象反模式+安全模式+regex/AST 检测器 → git 原生版本化 Lesson → 任意 agent 编码前 top-K 检索 → 编码后/CI 硬门禁）没有任何一个产品全部覆盖，但每一步都有强近似者在蚕食：(1) 检索/记忆半场已商品化 — Byterover CLI（原 Cipher，github.com/campfirein/cipher，4.9k stars，git 式 branch/commit/merge/push 版本化知识树 + 22+ agent MCP 接入）是最接近的整体竞品；Memorix（github.com/AVIDS2/memorix）已自动捕获 errors/gotchas 并跨 Codex/Claude Code/Cursor/Gemini CLI 共享；mem0/OpenMemory（60.9k stars）有官方 Codex/Claude Code 集成。(2) 每个大厂 agent 都已内置自动记忆：GitHub Copilot Memory（2026-03 起 Pro 默认开启）、Claude Code auto-memory、Codex Memories（2026-04 preview）、Devin Knowledge、Windsurf Memories——"agent 从错误中学习"本身已不新鲜。(3) 蒸馏机制最接近的是 Gemini Code Assist review memory（2025-11：从 PR 评审分歧自动归纳可复用规则）和 Qodo auto-best-practices（把被采纳的建议月度挖掘成 best_practices.md）；(4) 执行半场最强在位者是 CodeRabbit Learnings（PR 反馈→持久 learnings + Error 模式 pre-merge 硬门禁，$60M B 轮），但锁在自家评审产品内、自然语言无确定性检测器。(5) 学术上 SWE-Exp（arXiv:2507.23361）、ReasoningBank、ExpeL 已证明"失败经验库注入"有效但未产品化。结论：单项全有先例，组合无人做——但这条护城河窄且两侧都在被侵蚀。

### Q2 「记忆胶囊」式共享 hub 可行吗？

可行但必须把安全当第一公民设计。首先澄清：「OpenClaw 记忆胶囊」并非官方功能——OpenClaw 记忆就是 workspace 里的 Markdown（MEMORY.md + 每日日志），"胶囊"是社区把 workspace 当可迁移捆绑包（openclaw migrate、openclawsoul.org 上分享 SOUL.md+memory 包）的民间实践。共享 hub 的先例真实存在：Engram（带私有团队工作区 + 10 万条公共记忆市场，是最接近 PitLore registry 构想的产品）、ClawHub、skills.sh、Smithery、Claude Code 插件市场、cursor.directory。但投毒风险已被血淋淋验证：ClawHavoc 事件中 Koi Security 2026-02-01 审计发现 ClawHub 2,857 个 skill 里 341 个（11.9%）恶意，2-16 增至 824 个（单一账号 hightower6eu 发布 677 个），主要手法是伪装"先安装此前置依赖"投递 Atomic Stealer，而审核仅要求"GitHub 账号≥1 周"。对 PitLore 的具体教训：① Lesson 文本会被注入 agent prompt，本身就是注入通道——必须用结构化 schema 禁止自由文本祈使指令；② 严禁 Lesson 内含任何"安装/执行"指令；③ regex/AST 检测器需沙箱执行（防 ReDoS/恶意 AST 规则）；④ 需要发布者身份溯源 + 自动扫描（学 skills.sh 用 Snyk/Socket、Smithery 用 Invariant mcp-scan）+ 安装遥测，而非事后举报；⑤ 热门领域（crypto 等）会被 typosquatting。PitLore 的结构化格式相比自由文本 skill 天然缩小注入面，这可以反过来当卖点讲。

### Q3 本地/企业私有化部署可行吗？

完全可行，且是全场先例最充分的一环。技术路径全部验证过：git 原生本地文件做 agent 知识已被 Claude Code MEMORY.md、Letta Code MemFS（git 同步）、Qodo best_practices.md、.cursor/rules、.devin/rules 证明；本地 MCP server 是标准做法（Memorix、Byterover、mem0 self-hosted server、官方 server-memory 全是 local-first）；CI 硬门禁在 Semgrep/Codacy 等有成熟形态。企业私有化需求也有旁证：CodeRabbit 自托管仅限企业版（说明企业愿为此付钱）、mem0 官宣用 self-hosted server 接替弃用的 OpenMemory 本地栈、Copilot Memory 云锁定+28 天过期恰是企业痛点。PitLore 的 git-friendly 纯文件设计比 Memorix 的 ~/.memorix SQLite 或 Byterover 的云同步更适合"调试知识=公司资产"叙事（可 review、可 diff、可进内网 GitLab）。两个诚实的难点：① "不含专有代码"的 sanitization 无法纯自动保证——Codex Memories 官方文档都警告记忆可能含 secrets，必须设计人工 review 关卡 + secret 扫描（可复用 gitleaks 类工具），一次泄漏就毁掉企业 IP 叙事；② 企业采购要 SSO/审计日志/RBAC，这是 roadmap 项不是 hackathon 项。

### Q4 类 GitHub 公私 debug 仓可行吗？

可行且分发需求已被反复验证，但这是网络效应长跑，不是 hackathon 可交付物。先例：分发需求侧 — awesome-cursorrules ~40k stars、cursor.directory（67k+ 成员）、anthropics/skills、Continue Hub 版本化 rule blocks 证明开发者渴望共享 agent 规则；打包机制侧 — vibe-rules 已实现"规则装进 npm 包 llms export 自动安装"，Semgrep Registry（~2,500+ 规则）和 CodeQL packs（GHCR 上 semver）证明"版本化可安装的代码检查规则包"是成熟模式；市场侧 — Engram 已有 10 万条公共记忆市场。所以"人人有 debug 仓库、公开或私有"没有技术障碍：git 仓库即 Lore、registry 即索引层，甚至 v1 可以直接用 GitHub 本身托管（像 Claude Code plugin marketplace 用 git repo 做市场）。真正的障碍是冷启动与治理：① 双边市场无内容则无用户——需官方预置种子 Packs（可从 CWE/OWASP 映射 + 知名 OSS postmortem 蒸馏）；② ClawHub 教训表明开放上传必遭双位数比例投毒（见 Q2）；③ 差异化必须守住"经验蒸馏而来的版本化 Lesson"——如果退化成又一个 prose rules 目录，cursor.directory 和 rulesync/Ruler（29-30+ agent 分发）已经把静态规则分发做完了。建议：hackathon 只演示 registry 的 install UX（pitlore install pack@1.2.0），网站本体放 roadmap。

## 最接近的竞品（对抗验证通过）

### Byterover CLI（原 Cipher）

- URL: https://github.com/campfirein/cipher
- 最接近的整体竞品：git 式版本化（branch/commit/merge/push/pull）知识树 + 22+ agent MCP 接入 + 团队云同步，覆盖 PitLore 的版本化/跨 agent/分享三环；缺 bug-fix 蒸馏 schema、检测器、硬门禁、公共 registry。4.9k stars，活跃。

### CodeRabbit Learnings

- URL: https://docs.coderabbit.ai/knowledge-base/learnings
- 执行半场最强在位者：从 PR 评论反馈生成持久 org/repo 级 learnings 自动应用于未来评审，且有 Error 模式 pre-merge 硬门禁（$60M B 轮）。但锁在自家产品、自然语言无确定性检测器、不可被 Codex/Claude Code 编码时消费、非 local-first。

### Memorix

- URL: https://github.com/AVIDS2/memorix
- 精神上最接近的 OSS：hooks 自动捕获 decisions/errors/gotchas（带降噪过滤）+ 跨 10+ agent 一键 MCP 接入。但存 SQLite 非 git 内版本化文件、无抽象蒸馏、无检测器、无门禁，分享是未建的 Phase 7 roadmap。

### GitHub Copilot Memory

- URL: https://github.blog/changelog/2026-01-15-agentic-memory-for-github-copilot-is-in-public-preview/
- 'agent 从自身工作中学习'叙事的最强在位者（Pro 默认开启，coding agent/code review/CLI 共享记忆）。但云托管、repo 隔离、28 天过期、不可导出、仅建议性、Copilot 独占——每条都是 PitLore 的反面卖点。

### Gemini Code Assist review memory

- URL: https://cloud.google.com/blog/products/ai-machine-learning/memory-for-ai-code-reviews-using-gemini-code-assist
- 蒸馏机制上最接近 PitLore 核心环：从 PR 评审分歧自动归纳泛化可复用规则并用于未来评审自我过滤。但规则黑箱存于 Google 云、不可查看/导出/版本化、仅 Gemini 评审 bot 消费、无门禁；消费者版 2026-07-17 关停。

### mem0 + OpenMemory MCP

- URL: https://mem0.ai/openmemory
- 心智占有率最高的通用 agent 记忆层（60.9k stars），有官方 Codex/Claude Code/Cursor 集成（生命周期钩子自动抓 learnings + 响应前检索）。但通用事实/偏好记忆，无 lesson schema、无检测器、无门禁、无 packs/registry。注意 OpenMemory 本地栈已官宣弃用。

### Claude Code 内置四件套（auto memory + hooks + plugins/marketplaces）

- URL: https://code.claude.com/docs/en/memory
- 单厂商最深重叠：自动记忆捕获调试洞见、PreToolUse hooks 可确定性拦截、git 市场分发插件——四大支柱全有原语。但各层互不连通（记忆不会变成 hook 或插件）、仅 Claude Code 可用、无蒸馏/检测器/CI 模式。对 Claude Code 用户构成'为何不用内置'直接质疑。

### Semgrep Registry/Guardian + Codacy Guardrails（执行侧红海）

- URL: https://semgrep.dev/r
- '编辑后检查+硬门禁'半场已是专家规则红海：Semgrep ~2,500+ 版本化规则、Guardian 非可选扫描每次 agent 写文件、Codacy Guardrails IDE 内自动修复 AI 代码、SonarQube MCP。它们是手写专家规则无学习回路——但证明 PitLore 的 gate 形态用户已被教育过。

## PitLore 差异化（守住这些）

1. 结构化 Lesson schema：bug-fix 经验 → 反模式+安全模式+可执行 regex/AST 检测器。全场没有任何产品输出这个格式——CodeRabbit/Gemini 是自然语言、Copilot/Codex 是原始笔记、Semgrep 是专家手写。Getafix（Meta 内部）和 CODESKILL（arXiv 2026）证明蒸馏可行但未产品化。
2. 从学到的教训生成确定性硬门禁：所有记忆类产品都是建议性的（Claude Code 文档明确声明记忆'不是强制配置'）；唯一的确定性拦截（Claude hooks、Semgrep）与学习回路无关。'学到的教训能 block CI'是全场空白。
3. 真跨 agent：MCP 编码前 top-K 按任务检索（非 AGENTS.md 式全文常驻注入），Codex/Claude Code/Cursor/Gemini/Grok 同一 Lore。现有自动记忆全部厂商锁定，跨厂商可移植的只有手写静态规则。
4. git 原生、人工可 review、版本化的 Lesson——直接回应最尖锐的反证论文《Useful Memories Become Faulty》（LLM 自主固化记忆随时间退化到低于无记忆基线）：PitLore 的人审+版本化恰是论文指出的解法方向。Cursor 砍掉 Memories 改推显式 Rules 也佐证市场要可审查工件。
5. Sanitization 承诺（不存专有源码）→ 唯一把'调试知识=可跨边界分享的公司资产'讲通的定位；Codex Memories 官方文档自己警告记忆可能含 secrets 且设备锁定不可移植。
6. 软硬结合的完整回路：编码前软注入 + 编码后硬检查在同一 Lesson 上闭合。学术验证充分（SWE-Exp 73.0% Pass@1 SWE-bench Verified、ReasoningBank +4.6pt、Rakuten 用 Anthropic 记忆首过错误 -97%）但无人产品化为跨 agent 层。
7. npm 式 semver Lesson Packs + 公私 registry：现有 registry（cursor.directory、vibe-rules、Semgrep）只分发手写 prose 或专家安全规则，无'经验衍生的版本化教训包'。

## 风险清单

1. Lesson 投毒 + prompt 注入：ClawHub 开放上传 11.9% 恶意（341/2,857，两周增至 824）；Lesson 文本被注入 agent prompt 本身就是攻击通道，检测器（regex ReDoS、恶意 AST 规则）也是执行面。Registry 若无 provenance+扫描+schema 约束，必重演 ClawHavoc。
2. 上下文污染与检索退化：ReasoningBank 发现 k=1 检索最优、教训越多反而伤性能；《Useful Memories Become Faulty》显示 GPT-5.4 经记忆固化后丢失 54% 已解问题。PitLore 的 top-K 注入需要严格的相关性门槛和数量上限，否则'越用越笨'。
3. 硬门禁误报疲劳：自动从 bug-fix 蒸馏的 regex/AST 检测器精度必然低于 Semgrep 多年专家策展；误报率一高，团队第一反应就是关掉 gate——这会同时杀死'enforcement'这个核心差异化。需要 warn-first 默认 + 每条检测器命中率遥测 + 一键降级。
4. 冷启动：空 Lore 第一天零价值，而 Copilot Memory/Claude auto-memory 默认开启免费给捕获。必须靠预置种子 Packs + 从已有 git 历史/issue 回溯挖掘存量教训来解。
5. 双向商品化挤压：捕获半场被各家内置记忆蚕食（Copilot 默认开、Codex Memories preview），门禁半场被 Semgrep Guardian/Codacy/SonarQube MCP 占住，可移植性叙事被 AGENTS.md（60k+ repo 事实标准）稀释。组合窗口真实但在收窄，大厂随时可能把三者捆起来。
6. Sanitization 无法硬保证：LLM 抽象化可能泄漏专有标识符/密钥/业务逻辑，一次企业客户泄漏事故即摧毁'私有资产'定位；人审关卡又增加采用摩擦。这是产品最脆的承诺。
7. 蒸馏质量是最难的 ML 问题：把具体 fix 泛化成'正确且通用'的反模式极易过泛化（把特例当规律）或欠泛化（无迁移价值），坏教训比没教训更糟。Meta Getafix 靠海量内部数据才做成，hackathon 版本蒸馏质量将直接决定 demo 成败。
8. 竞争者资本与规模劣势：Byterover/mem0 有融资和万级 star 社区，CodeRabbit $60M 且已进企业采购流程；registry 网络效应是多年长跑，与 hackathon/早期团队的时间线错配。

## 历史 OpenAI Build Week 定位建议（已停止执行）

1. Demo 就是闭环本身，一镜到底：在 Codex CLI 里现场引入一个经典 bug → 修复 → PitLore 自动蒸馏出 Lesson（展示 anti-pattern/safe-pattern/detector 三段结构）→ 开全新会话让 Codex 写同类代码，MCP 检索到 Lesson 主动规避 → 故意绕过后 `pitlore check` 在 CI 里红灯拦截。没有任何在位者能演完这个循环——这是唯一能在 5 分钟内讲清差异化的方式。
2. Codex 优先叙事（这是 OpenAI Build Week）：定位为'Codex Memories 给不了的那层记忆'——引用 OpenAI 自家文档：Memories 设备锁定、不可移植、可能含 secrets、OpenAI 自己说持久规则该放 AGENTS.md/checked-in docs。PitLore = 那个 checked-in、版本化、可执行的形态。再演示同一份 Lore 同时喂 Claude Code/Cursor，证明可移植。
3. 把硬门禁做成 wow moment：评委见惯了'agent 会记住偏好'（Copilot/Codex/Claude 全有），但没见过'上周的 bug 变成今天 CI 里一条会拦截的确定性检测器'。让红色的 CI 失败成为 demo 高潮帧。
4. 用预置 Packs 杀掉冷启动质疑：现场 `pitlore install nextjs-app-router-pitfalls@1.0.0`（或 async-python-gotchas），Lesson 标注 CWE ID 映射，一并展示 npm 式安装 UX——同时回答了冷启动和 registry 可行性两个必问问题。
5. 主动打预防针（评委里有 ML 背景的人必问）：一页 slide 直面《Useful Memories Become Faulty》和 ReasoningBank 的 more-lessons-hurt 发现，解释为什么人审+git 版本化+top-K 限额的设计恰好是论文指出的解法，而不是被它证伪。
6. Registry 安全一页纸：引用 ClawHavoc 具体数字（11.9% 恶意、824 个、'装前置依赖'手法），说明 PitLore 的结构化 schema 禁自由祈使文本、检测器沙箱执行、发布者签名+自动扫描（对标 skills.sh 的 Snyk/Socket、Smithery 的 mcp-scan）。把最大风险转化为'我们是唯一为此设计过的团队'。
7. 范围纪律：只把 local-first 闭环（capture→distill→retrieve→check）作为已交付，Packs registry 网站放 roadmap 一页。评委对'又一个双边市场'免疫，但对'今天就能跑的完整回路+清晰的商业化阶梯（个人免费→团队私有 Lore→企业自托管）'买账。

## 附录 B：各调研角度摘要

### Agent 记忆系统

The "memory for coding agents" space is crowded in 2025-2026: generic cross-agent MCP memory layers (mem0/OpenMemory, Byterover/Cipher, Memorix, plus dozens of knowledge-graph MCP servers) already deliver PitLore's retrieval half — local-first storage, top-K recall before coding, and compatibility with Claude Code/Codex/Cursor/Gemini CLI — and every major agent now ships builtin memory (Claude Code auto-memory MEMORY.md, Devin Knowledge, Windsurf Memories; Cursor killed Memories in favor of Rules). The closest single competitor is Byterover CLI (formerly Cipher, 4.9k stars, active), which even has git-like branch/commit/merge/push versioning of a shared knowledge tree across 22+ agents. However, NO found product combines PitLore's specific stack: lessons mined specifically from bug-fix experiences, stored as sanitized abstract anti-pattern/safe-pattern pairs (no source code), with machine-checkable regex/AST detectors and a hard blocking check gate in CI — enforcement today lives only in adjacent products like CodeRabbit's Learnings (natural-language review memory, advisory not deterministic) and hand-written Semgrep/ast-grep rules (deterministic but manually authored, no memory loop). The npm-like packs/registry roadmap also has partial precedent in cursor.directory, vibe-rules (rules shipped inside npm packages), and Ruler/rulesync cross-agent distribution, but those distribute static hand-written prompts, not versioned experience-derived lessons. Academic work (ExpeL, Reflexion, Agent Workflow Memory, and especially SWE-Exp arXiv:2507.23361 — a multi-faceted "experience bank" distilled from successful AND failed repair trajectories, +Pass@1 on SWE-bench) validates the core thesis but is unproductized. Net: PitLore's retrieval side is commoditized; its defensible novelty is the detector/hard-gate enforcement loop plus sanitized shareable lesson packs as private IP.

### 编辑器/Agent 内建功能

By mid-2026, every major AI coding tool ships BOTH a manual persistent-rules layer (CLAUDE.md, AGENTS.md, .cursor/rules, copilot-instructions.md, GEMINI.md, .amazonq/rules) AND, increasingly, an automatic memory layer that distills learnings from sessions and corrections: GitHub Copilot Memory (default-on for Pro since 2026-03), Claude Code auto-memory, OpenAI Codex Memories (preview, 2026-04), Devin Knowledge, Windsurf Cascade Memories, and — closest to PitLore's core loop — Gemini Code Assist's code-review memory (2025-11), which automatically infers generalized reusable rules from PR-review disagreements. So "agent that learns from mistakes and persists rules" is no longer novel as a built-in feature. However, all automatic memories are vendor-locked (Copilot's even expire after 28 days), stored as raw natural-language facts rather than sanitized abstract anti-patterns, advisory-only (no hard gate; the sole deterministic blocker, Claude Code hooks, is hand-written shell scripts unrelated to learned lessons), and none offer versioning, regex/AST detectors, CI enforcement, or a cross-vendor registry. PitLore's defensible whitespace is the integration: automatic distillation → sanitized versioned lesson → cross-agent MCP retrieval → enforceable check/CI gate → npm-like packs; each pillar exists somewhere in isolation but no vendor or community project combines them, and portability across agents exists only for manually-written AGENTS.md-style rules.

### AI 代码评审学习机制

"Learning from past reviews" is now table stakes in commercial AI code review: CodeRabbit Learnings, Cursor Bugbot learned rules (44k+ auto-generated rules across 110k+ repos), Greptile memory, Qodo auto-best-practices, Bito learned rules, and Ellipsis inferred rules all accumulate team-specific knowledge from review feedback — so PitLore's core premise is well validated but crowded. However, nearly all of them learn review-feedback CONVENTIONS (style, preferences, false-positive suppression) rather than distilled bug ROOT-CAUSE anti-patterns, and the learnings live in vendor clouds, not portable artifacts: CodeRabbit only exports CSV re-importable into CodeRabbit, Bugbot rules are locked to Cursor, and none expose learnings via MCP for arbitrary coding agents (Codex/Claude Code/Gemini) to consume BEFORE writing code. Sentry Seer AI Code Review is the only one that feeds real production bug history into PR review, but as raw telemetry, SaaS-only, not versioned lessons. Git-friendly artifacts exist only in fragments (Qodo's best_practices.md wiki, Greptile's .greptile/ rules, Sourcery's .sourcery.yaml pattern rules, Bito's .bito.yaml), and hard CI gates exist only in non-learning tools (Codacy quality gates, Sourcery CLI). The closest architectural match to PitLore's portable cross-agent layer is the OSS agent-memory category (ByteRover Cipher/brv, github.com/campfirein/cipher — MCP memory shared across Cursor/Claude Code/Gemini CLI, self-hostable) but it stores raw session memories in vector DBs, with no anti-pattern/safe-pattern schema, no regex/AST detectors, no CI gating, and no versioned pack registry. Net: every individual ingredient exists somewhere, but no product combines bug-fix→versioned abstract lesson distillation + git-native local-first storage + agent-agnostic MCP pre-code injection + hard CI gate + npm/GitHub-style lesson registry.

### OpenClaw 记忆胶囊与共享 hub

"OpenClaw memory capsule" is NOT an official feature: OpenClaw's memory is plain Markdown files in the workspace (MEMORY.md curated long-term, memory/YYYY-MM-DD.md append-only daily logs, SOUL.md personality, skills/ capabilities) plus hybrid BM25+vector retrieval and a pre-compaction "memory flush"; the "capsule" the user remembers is almost certainly a blend of (a) the popular guides' "time capsule" metaphor for stale MEMORY.md, (b) the viral practice of treating the workspace as a portable bundle — `openclaw migrate` moves the whole agent, people publish/download SOUL.md+memory bundles on GitHub directories like openclawsoul.org, and plugins (Mem0, supermemory, Hindsight, Tenure, Tablestore) sync memories across agents. The ClawHub poisoning incident is verified and severe: Koi Security's 2026-02-01 audit found 341 of 2,857 skills malicious (11.9%), 335 in the "ClawHavoc" campaign delivering Atomic Stealer via fake "install this prerequisite" instructions; it grew to 824 malicious skills by Feb 16 (registry 10,700+, one actor "hightower6eu" published 677), with moderation being only "GitHub account ≥1 week old" and the fix being reactive community reporting (3 reports auto-hides). Key registry lessons for PitLore: open-by-default upload gets poisoned at double-digit rates, lesson text that agents prompt-inject is itself an injection channel, "prerequisite install" instructions must be banned from lessons, typosquatting targets hot niches (crypto), and trust needs publisher provenance + automated scanning (skills.sh uses Snyk/Socket, Smithery uses Invariant mcp-scan) + install telemetry, not just reports. The skill/knowledge-sharing hub space is crowded (ClawHub, skills.sh, Smithery, Claude Code plugin marketplaces, lobehub), and the closest product to PitLore's registry idea is Engram (MCP shared memory for coding agents with private team workspaces, confidence scoring, and a 100k-item public memory marketplace) — but nobody combines versioned, sanitized anti-pattern/safe-pattern Lessons with regex/AST detectors, a hard post-edit/CI blocking gate, and git-native local-first private repos; that pre-code soft injection + post-code hard gate + lesson provenance combination remains PitLore's open lane.

### 规则/反模式注册表生态

PitLore's two halves each exist and are crowded separately, but no product closes its full loop. Half one — expert-written rule registries with versioned packs and CI gates — is mature (Semgrep Registry ~2,500+ rules, CodeQL packs with semver on GHCR, ESLint's npm plugin ecosystem, SonarQube rules), and in 2025-26 every major vendor repackaged this for AI agents via MCP/hooks (Semgrep Guardian scans every agent file-write non-optionally, Codacy Guardrails auto-fixes AI code in-IDE, SonarQube MCP Server): the "check after edits + hard gate" half is now a red ocean of expert rules. Half two — capturing lessons from actual dev experience and feeding them back to agents — exists as unstructured memory/prose: ByteRover/Cipher (OSS MCP memory layer, ~5k stars), CodeRabbit Learnings (distills team preferences from PR comments and enforces them in future reviews), Devin Knowledge, Cursor Memories (notably killed in v2.1), Claudeception/ECC "instincts", and YC startup Glen; prose-rules marketplaces (awesome-cursorrules 40k stars, cursor.directory, Continue Hub versioned rule blocks, anthropics/skills 161k stars) prove distribution demand. What nobody ships: bug-fix → sanitized structured lesson (anti-pattern + safe pattern + regex/AST detector) → semver-versioned installable pack → agent-agnostic top-K retrieval BEFORE coding plus detector-backed CI blocking AFTER — Getafix (Meta, internal) and CODESKILL (arXiv 2026) prove the distillation step is feasible but neither is productized as a registry. PitLore's differentiation is real but narrow and eroding from both sides; its defensible core is the structured lesson schema with attached detectors, git-native private-by-default packs, and cross-agent portability.

### 学术研究

The academic record strongly validates PitLore's core mechanism while leaving its productization layer open. A clear lineage — Reflexion (91% HumanEval via verbal failure memory, +8 pts over raw-trajectory memory), ExpeL (do/don't insights distilled from failed-vs-successful trajectories), AWM (+51.1% relative on WebArena from induced reusable knowledge), and for code specifically SWE-Exp (73.0% Pass@1 SWE-bench Verified using an experience bank of successful AND failed repairs) and Google's ReasoningBank (SWE-bench Verified 34.2%->38.8% with 2.8 fewer steps/task; failure-derived memory items explicitly help; but k=1 retrieval optimal, more lessons hurt) — proves that injected lessons, including negative ones, measurably reduce repeat errors and wasted exploration; LessonL and the failure-aware negative-knowledge-bank paper (arXiv 2606.21024) plus SWE-Bench-CL and Memento (case-based memory, +4.7-9.6 pts OOD) round out the space. Industry has already shipped the mechanism in 2026: Anthropic's managed-agent memory/'Dreaming' (Rakuten: 97% fewer first-pass errors, 27% lower cost) and OpenAI Codex's built-in /memories auto-distillation — so 'agents that learn lessons' is no longer novel, it's the default trajectory of both frontier vendors. The sharpest counter-evidence is 'Useful Memories Become Faulty' (May 2026): autonomous LLM consolidation of experiences into abstract lessons degrades below no-memory baselines over time (GPT-5.4 loses 54% of previously solved ARC-AGI problems; raw episodes double forced-consolidation accuracy), and ACE similarly documents brevity-bias/context-collapse — findings that actually argue FOR PitLore's human-curated, git-versioned, reviewable lessons over auto-rewritten memory, but which PitLore must address head-on. No academic or vendor system combines PitLore's specific bundle: sanitized anti-pattern+safe-pattern lessons with executable regex/AST detectors, a hard CI gate, npm-style versioned packs, a public/private registry, and vendor-neutral MCP distribution across Codex/Claude/Cursor/Gemini — that composition remains unclaimed prior-art-wise, though every individual ingredient now has strong precedent.
